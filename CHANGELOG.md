- Dispatch Packet Contract v1 (Issue #102 slice 102a, PR #103, merged as `cbb2b3a`): `docs/workflow/dispatch-packet-contract.md` defines the required shape and discipline rules for the prompt a parent agent writes when spawning a child agent — a nine-mandatory-field template (`Packet`, `Role`, `Repo state`, `Objective`, `Authoritative source`, `Scope`, `Verify`, `Return`, `Fallback`) plus four conditional fields, five discipline rules (no restatement, no history, no pre-judgment, negative space is load-bearing, repo gates belong to the packet), seven role content selectors, a versioned changelog, and Known Limitations. Referenced once from `AGENTS.md` and registered in `PROJECT_INDEX.md`; `docs/templates/WORK_ITEM.md` gains a `Packet version: / Packet tokens:` field beside `Rework cycles:` so evidence accrues from real work items rather than a synthetic corpus. Documentation-only — no `.mjs`/`.js` changed, tests unchanged at 207. The design deliberately abandons the original proposal's context-budget justification: the median dispatch packet measured 1,087 tokens across 59 real dispatches, or 4.2% of the 25,980-token canonical reading set, so compression saves roughly 2.7% of a child's context. The value proposition is instead single-sourcing and non-contamination, grounded in two failure modes measured by decomposing real packets — restatement of the authoritative source (~700 of 1,198 tokens, and the origin of Issue #99's spec-versus-paraphrase divergence) and pasted history with pre-judged findings (~330 tokens in the QA packet, which stated its expected conclusion before the reviewer looked). Both agent dispatches in this work item were themselves written using the contract; the implementer followed the packet and reported a packet-versus-design conflict rather than improvising, and QA disagreed on one of three unjudged items, catching a genuine weakening. The deferred 102b evaluation slice was reduced from a nine-cell/36-run corpus to 3 synthetic blocked-case cells (12 runs), opened only on a declared numeric trigger.

- Governing-workflow declaration guidance was incomplete (Issue #111, PR #114, merged as `cb8a9e2`): the GitHub PR template backtick-wrapped the required `Governing workflow: Bug Fix` declaration, so a good-faith author who copied it literally (backticks included) failed the anchored regex — the opposite failure direction from Issue #108, which closed a bypass rather than an over-block. Reworded the guidance as plain prose with an explicit "no backticks, no quote marker" instruction, and added the same guidance to `.gitlab/merge_request_templates/Default.md`, which previously had none. Deliberately did not loosen the regex, to fix root cause rather than one transcription shape. `npm test` 219 → 223; a full repository-wide sweep confirmed Issue #108's zero-effort-bypass property was not regressed.
- `work-item-readiness-freshness` had no Bug Fix workflow carve-out (Issue #108, PR #109, merged as `9408abe`): `validateReadiness()` required every linked Issue to carry `status:spec-ready`/`status:development-done`/`status:verification-done` unconditionally, permanently blocking every legitimate Bug Fix PR since `AGENTS.md` documents that Bug Fix work items correctly never carry those labels. Fixed with a two-signal carve-out (`bug` label + a line-start `Governing workflow: Bug Fix` PR-body declaration) after 4 independent QA passes found and closed two real gaps: a label-only check would let a mislabeled Issue silently bypass the gate, and the first declaration regex was unanchored and matched the PR template's own guidance prose. Anchored to `/^Governing workflow:\s*Bug Fix\b/im`; a repository-wide sweep confirmed zero tracked files satisfy it unedited. `.github/pull_request_template.md` documents the field. `npm test` 207 → 217.
- `validate-review-gate` could never fail (Issue #106, PR #107, merged as `812e7df`): `hasReviewRecord()` checked only whether any `*-code-review.md` file existed anywhere in `docs/records/qa/`, and 10+ such files were already committed permanently. Fixed to accept only a review record added in the current diff (`git diff --diff-filter=A`) at the canonical path. Independently re-verified outside the Codex host after its own in-turn QA dispatch timed out three times. `npm test` 207 → 209.
- Audit script exit-code bug (Issue #49 AC-2, commit `6b54d71`): `scripts/housekeeping-worktrees.mjs` never called `process.exit(1)` — the CI audit step would always pass even with ghost worktrees accumulated. Fixed by setting `process.exitCode = 1` in dry-run mode when prunable worktrees are detected, and when dirty worktrees are skipped after `--prune`. QA caught this in the first verification round; fix was re-verified PASS in the second round.
