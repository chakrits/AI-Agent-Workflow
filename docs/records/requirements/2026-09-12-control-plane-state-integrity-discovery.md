## 3. Assumptions

| # | Assumption | Impact if Wrong | Validation Needed |
|---|---|---|---|
| 1 | Upgrading active shards to envelope v2 does not conflict with the workflow policies, because the two version numbers govern different layers: the shard carries `contract_version: 2` (envelope) and `policy_contract_version: 1` (policy), and the validator cross-checks only the latter. | If the validator keeps comparing `contract_version` against `policy.contract_version`, every backfilled shard fails validation immediately. | Run `npm run validate:contracts` over every fixture discovered in the example lane (enumerated dynamically, not by count) and over the migrated active shards. |
| 2 | Enforcing `matrixEntry.actors` strictly validates transition policy against caller-declared role identity without requiring cryptographic agent signatures. | Overly rigid actor checks could reject emergency overrides or legitimate backward routing handoffs. | Explicitly verify actor matrix covers orchestrator and human override roles where permitted in `TRANSITION_MATRIX`. Document residual trust boundary risk. |
| 3 | The property that prevents a lost update is the **unconditional CAS check inside the critical section**, not the lock: `mutateTaskStateOnDisk` re-reads disk state and compares `expected_digest` regardless of how the lock was obtained. The `wx` lock at `docs/records/work-items/.locks/{task_id}.lock` (never force-reclaimed, never inside the shard directory) provides mutual exclusion and orderly serialization on top of that. The equivalent guarantee for `PROJECT_STATUS.md` requires the separate projection lock of BR-005; the shard lock alone does not provide it. | Scripts transitioning without reading current state first are rejected with `MISSING_EXPECTED_DIGEST` or `CAS_CONFLICT`. A lock whose PID is dead stops that shard until an operator runs the maintenance-only `unlock --quiesced`; a lock held by a live but slow holder is never routed into recovery and surfaces as `LOCK_ACQUISITION_TIMEOUT` + `LOCK_HELD_LONG`. If the CAS argument is wrong, a wrong operator quiescence judgement becomes a silent lost update instead of a detected `CAS_CONFLICT`. | Deterministic barrier-synchronized multi-process tests for both locks, the lock-order test, and a test that a mutation whose lock was removed by `unlock` still fails `CAS_CONFLICT`. |
| 4 | Failing closed on malformed shards in `compileStatusProjection` via a shared validation seam (`validateEnvelopeSchema`) will prevent corrupt data from being silently excluded from project status. | A single malformed test file or scratch shard could block compiler runs across unrelated shards. | Ensure test fixtures create isolated temporary mock workspaces during unit tests. |

| # | Question | Owner | Blocks Progress? |
|---|---|---|---|
| 1 | Is the durable envelope the sole contract authority, or does it layer over the existing `*-workflow.yaml` policies that `AGENTS.md` names canonical? | SA / Human | Resolved (Round 4): Layered, not sole. Envelope owns storage shape at `contract_version: 2`; policies keep owning transitions, evidence and retry budget at `contract_version: 1`; the envelope's new `policy_contract_version` binds the two and is what the validator cross-checks (ADR-0026). The envelope's `workflow_id` is narrowed to `bug-fix` for Package 1, because the fixed state vocabulary cannot represent `new-feature`, `config-change` or `data-change`, and `framework-meta` has no canonical policy at all. |
| 2 | For CLI commands (`scripts/task-machine-cli.mjs`), should an optional `--force` flag exist for emergency Human Maintainer bypass of CAS digests, or must CAS always be strictly computed and supplied? | Security / SA | Resolved: CAS must always be strictly supplied; provide `inspect` command to display current digest for auditability without blind bypasses. |
| 3 | When `scripts/archive-work-item.mjs` moves a terminal shard, should it execute transactional archival with compensating rollback if status projection fails? | SA / Dev | Resolved: Implement two-phase archival with compensating directory restoration (ADR-0029). |
| 4 | Should an abandoned shard lock be reclaimed automatically after a staleness threshold? | SA / Security | Resolved (Round 4): No. No `fs` primitive makes removal conditional on the observed lock, so every automatic-reclaim variant can remove a live replacement owner. Fail closed with `LOCK_ABANDONED` and an explicit nonce-verified `unlock` command (ADR-0027). — **Amended (Round 5, Blocker 4, ADR-0027 amended):** still no automatic reclaim, and two further corrections. (a) Staleness is no longer an abandonment classifier at all: abandonment is **dead PID only** (`process.kill(pid, 0)` throws `ESRCH`), while age alone yields the non-destructive diagnostic tier `LOCK_ACQUISITION_TIMEOUT` + `LOCK_HELD_LONG`, so a live but slow holder can no longer enter the recovery path. (b) The Round 4 claim that nonce verification makes `unlock` race-safe — and the undefined "`wx` sentinel" it relied on — is **withdrawn**. `unlock` is a maintenance-only operation requiring an explicit `--quiesced` operator assertion; the nonce is retained only as an operator-mistake filter. Integrity is carried by the unconditional CAS check, not by `unlock`. |
| 5 | Is atomic replacement of `PROJECT_STATUS.md` sufficient to prevent lost updates to the root projection? | SA / Human | Resolved (Round 4): No. Atomicity prevents torn bytes, not read-compile-write interleaving. A projection-level mutation lock with a declared total lock order is required (ADR-0030). |

## 5. Scope

### In Scope
- **Core Pain Point 1 (Two-Layer Contract Model, `bug-fix`-Scoped Envelope - F-01, ADR-0026, ADR-0031):** Establish an explicit two-layer contract model rather than a single authority. The **storage envelope** layer (`docs/contracts/schemas/durable-task-envelope.schema.json`, `contract_version: 2`) owns file shape: the 11-state storage vocabulary, 64-char hex SHA-256 `state_digest`, strictly incremented `sequence_number`, history record shape. The **workflow behaviour** layer (`docs/contracts/{bug-fix,new-feature,config-change,data-change}-workflow.yaml`, `contract_version: 1`, unchanged) keeps owning allowed transitions, required evidence and retry budget, exactly as `AGENTS.md` states today. The envelope records `policy_contract_version` binding it to its governing policy, and `scripts/validate-contracts.mjs` cross-checks that field instead of `contract_version`.
  - **Package 1 durable scope is `bug-fix` only (ADR-0031).** The envelope's `workflow_id` and `change_type` enums are narrowed to `["bug-fix"]`, because the fixed 11-state vocabulary cannot represent the states `new-feature`, `config-change` and `data-change` policies require, and no `framework-meta-workflow.yaml` exists (verified: `docs/contracts/` contains only the four policies above). Both live active shards (`issue-249`, `issue-275`) are already `bug-fix`, so the narrowing migrates nothing. **Consequence, recorded deliberately:** `new-feature`, `config-change`, `data-change` and `framework-meta` — including Issue #277 itself — have **no durable shard** in Package 1 and remain governed by their policies and the existing example lane. The state enum itself is *not* narrowed: it stays a superset of the `bug-fix` policy's states (retaining `designing`/`planning`); the intersection rule, not the enum, does the narrowing.
  - **Single authority rule.** A transition is permitted **if and only if** it appears in both `TRANSITION_MATRIX[from].destinations` and the governing policy's `transitions` list, with the evidence keys on **that policy row** present. No matrix fallback for policy-silent transitions, no envelope-only allowlist, no exception contract; the matrix's `requires` is a design-time authoring aid never consulted at validation. Unknown `workflow_id`, unknown source state and policy-silent transition all fail closed.
  - `bug-fix-workflow.yaml` is amended additively with `completed`/`cancelled` states and a `handoff -> completed` transition requiring `closeout_evidence`, so that terminal migration is legal under policy. Under the authority rule this leaves `cancelled` a valid **storage** state and a declared matrix terminal that is **unreachable by transition** in Package 1, since the policy enumerates no `-> cancelled` row; no wildcard semantics are introduced. `AGENTS.md` is amended to state the split explicitly.
- **Core Pain Point 2 (Actor Policy Validation & Trust Boundaries - F-02):** Mandate enforcement of `matrixEntry.actors` check in `transitionTaskState()` for every transition against canonical `ROLE_REGISTRY`. Reject unauthorized role attempts with `UNAUTHORIZED_ACTOR` error code. Clarify scope as caller-declared role authorization and document residual risk.
- **Core Pain Point 3 (True Atomic CAS & Mutual Exclusion - F-03, ADR-0027 as amended, ADR-0028):** Make `expected_digest` mandatory for state transitions and resumes, checked unconditionally inside the critical section — this, not the lock, is what prevents a lost update. Implement a per-task mutual exclusion file lock in a **stable namespace that the archive rename never moves**: `docs/records/work-items/.locks/{task_id}.lock`, never `work-items/{task_id}/.lock`. The lock API is keyed by `task_id`, never derived from a directory path, so acquire, release, `inspect`, `unlock` and cleanup all address the same invariant pathname across an archive transaction. `discoverActiveShards()` must skip dot-prefixed entries under `docs/records/work-items/` **before** any shard-validity check (non-lossy: `task_id` is constrained to `^[a-z0-9_-]+$`), so strict active-shard validation does not reject `.locks/` or `.projection.lock`. **Fail-closed abandonment:** the engine never reclaims a lock automatically. Abandonment is classified by **dead PID only**; age alone is a non-destructive diagnostic tier (`LOCK_ACQUISITION_TIMEOUT` + `LOCK_HELD_LONG`) that never routes a live slow holder into a destructive path. Recovery is the **maintenance-only** `unlock --quiesced`, which is explicitly *not* race-safe and is not claimed to be; the nonce check is an operator-mistake filter (`LOCK_NONCE_MISMATCH`). Disk state is re-read under the lock inside a disk-bound mutation wrapper (`mutateTaskStateOnDisk`). Implement dedicated `digestTaskEnvelope(envelope)` which excludes top-level `state_digest` and computes canonical RFC 8785 JCS SHA-256 via `scripts/lib/status-jcs.mjs`.
- **Core Pain Point 4 (Fail-Closed Projection & Transactional Archival - W1, F-10, ADR-0029):**
  - Unified validation seam: implement `validateEnvelopeSchema(data)` shared across state machine, compiler, and backfill tools. Enforce schema structure and `stored state_digest === digestTaskEnvelope(data)`. Throw `MALFORMED_SHARD` on unparseable, invalid, or digest-mismatched shards.
  - POSIX crash-durable atomic writes: implement `atomicWriteFileSync` with collision-safe `wx` temp files, write completion loops, failure cleanup (`unlinkSync`), `fsyncSync` data flush, atomic rename, and directory sync. A `writeSync` return of `0` is a fault, not a retry condition: the loop must throw `ATOMIC_WRITE_NO_PROGRESS` and clean up its temp file rather than spin.
  - Pure projection with explicit repair: `compileStatusProjection()` and `detectArchivedShardDrift()` are pure and write nothing; repair lives only in `reconcileArchivedShards()`, reachable from archival preflight and an explicit `--reconcile` flag. `--check` writes zero bytes and exits 1 naming a recovery command.
  - Projection transaction: serialize `PROJECT_STATUS.md` mutation behind a projection-level lock and re-read active shards only after acquiring it, under the declared total lock order shard lock -> projection lock.
  - Transactional archival & crash recovery: implement two-phase `archiveWorkItem` with compensating rollback if projection compilation fails, plus preflight drift reconciliation (`reconcileArchivedShards`).

### Out of Scope
- Cryptographic agent identity verification or process authentication (caller-declared role policy validation only; full signature infrastructure deferred).
- Modifying production application business code or schemas outside control-plane state management.
- Modifying token budgets or Core Bootloader Tier 1 context limits ($\le 3,500$ tokens).
- Relaxing the 2-cycle rework retry ceiling or human approval gate invariants.
- Introducing external database engines or distributed network consensus mechanisms (remains Local-First, Git-Native, POSIX file-based).
- Automatic recovery from abandoned locks. Explicitly rejected in ADR-0027: recovery is an operator action.
- A race-safe `unlock`, and the lock-management sentinel that would be needed to provide one. Explicitly rejected in ADR-0027 as amended: `unlock` is maintenance-only and integrity rests on the unconditional CAS check.
- Durable envelopes and active-shard enforcement for `new-feature`, `config-change`, `data-change` and `framework-meta`. Deferred by ADR-0031 to a later package whose entry conditions are a canonical policy per workflow (`framework-meta` has none today) plus a policy-aware state vocabulary.
- Wildcard transition semantics (`<any> -> cancelled`) in `scripts/validate-contracts.mjs`, which performs exact `from -> to` lookup today. Any future cancellation path must be enumerated as explicit policy source rows.

## 8. Business Rules

| Rule ID | Rule | Source | Impacted Area |
|---|---|---|---|
| **BR-001** | **Two-Layer Contract Authority, `bug-fix`-Scoped Envelope, Single Authority Rule:** `durable-task-envelope.schema.json` is the sole authority for the storage envelope (`contract_version: 2`, 11-state storage vocabulary, digest, sequence), and in Package 1 its `workflow_id`/`change_type` are narrowed to `bug-fix` alone (ADR-0031). The `*-workflow.yaml` policies remain the sole authority for allowed transitions, required evidence and retry budget at `contract_version: 1`. Unknown `workflow_id`, unknown source state and policy-silent transition all fail closed. Legacy `task-state.schema.json` is retained for historical audit only. | Audit F-01, ADR-0026, ADR-0031, AGENTS.md L274-276 | Task State Machine, JSON Schemas, Workflow Policies, `validate-contracts.mjs`, AGENTS.md |
| **BR-002** | **Strict Matrix Actor Authorization:** Every state transition must enforce actor authorization against `TRANSITION_MATRIX[fromState].actors`. Canonicalize actor identifiers to lowercase kebab-case against `ROLE_REGISTRY`. Unauthorized transitions fail closed with `UNAUTHORIZED_ACTOR`. | Audit F-02, Least Privilege Principle | `scripts/lib/task-state-machine.mjs`, CLI |
| **BR-003** | **Mandatory CAS Verification & Fail-Closed Task Lock in a Stable Namespace:** All state modifications and resumes must supply `expected_digest` matching `digestTaskEnvelope()`, and must run inside `mutateTaskStateOnDisk`, which acquires the task lock, re-reads disk state under it, verifies CAS **unconditionally**, and releases in `finally`. The lock is `docs/records/work-items/.locks/{task_id}.lock`, keyed by `task_id` and never derived from a shard directory path, so the archive rename cannot move it. The engine never removes a lock it does not own: abandonment is classified by **dead PID only** and raises `LOCK_ABANDONED`; age alone yields `LOCK_ACQUISITION_TIMEOUT` + `LOCK_HELD_LONG`. Recovery is the **maintenance-only** `unlock --quiesced`, which is not race-safe; its nonce check is an operator-mistake filter only. Concurrent, stale, or wrongly-unlocked mutations are rejected with `CAS_CONFLICT`. | Audit F-03, ADR-0027 (as amended Round 5), ADR-0028 | `task-state-machine.mjs`, `task-machine-cli.mjs` |
| **BR-004** | **Fail-Closed Projection & Read-Only Checks:** Projection compilation must never skip malformed, invalid, or digest-mismatched shards silently. `compileStatusProjection()` and `detectArchivedShardDrift()` are pure and write nothing; repair exists only in `reconcileArchivedShards()`, reachable from archival preflight and explicit `--reconcile`. `--check` writes zero bytes and exits 1 with a named recovery command, and creates no lock namespace. Any other skip is the fail-open defect this rule forbids. | Audit W1, F-10, ADR-0027 (as amended), ADR-0029 | `compile-status-projection.mjs`, `archive-work-item.mjs` |
| **BR-005** | **Projection Transaction & Total Lock Order:** Every mutation of `PROJECT_STATUS.md` must hold the projection lock and must recompile active shards **after** acquiring it. The total lock order is shard lock -> projection lock; no path may invert it. The projection lock uses the same fail-closed abandonment policy as the shard lock. | Round 4 Blocker 4, ADR-0030 | `compile-status-projection.mjs`, `archive-work-item.mjs` |

## 9. Risk / Edge Case Notes

| Risk ID | Risk / Edge Case | Impact | Suggested Coverage |
|---|---|---|---|
| **R-001** | **Legacy Active Shard Incompatibility:** Shards for `issue-249` and `issue-275` currently have `contract_version: 1` and lack `sequence_number` and `state_digest`. | High | Provide a deterministic migration / reconciliation backfill script to upgrade active shards to v2 format prior to activating strict schema gates. |
| **R-002** | **CLI Tool Usability Friction with Mandatory CAS:** Requiring `expected_digest` on manual CLI invocations could make quick developer testing cumbersome. | Medium | Provide an `inspect` helper command that displays the current digest and any lock holder without mutating anything, so callers can supply the digest explicitly. |
| **R-003** | **Actor Name Formatting Drift:** Actor names may be supplied as `developer-agent` or `Developer Agent` (capitalized with spaces). | Medium | Canonicalize actor identifiers to lowercase kebab-case (`ROLE_REGISTRY`) before matching against `matrixEntry.actors`. |
| **R-004** | **Mid-Write Crash on File Operations:** Interrupting writes leaves files corrupted or truncated, or leaks temp files. | High | Implement `atomicWriteFileSync(targetPath, content)` with collision-safe `wx` temp files, catch-block temp unlink, `fsyncSync`, atomic rename, and directory sync. |
| **R-005** | **Archival Desynchronization & Crash Drift:** If process is killed between shard move and status file update, repository is left in drift. | High | Two-phase archival with compensating rollback on exception, plus preflight `reconcileArchivedShards` on archival and an explicit `--reconcile` flag. Detection runs on every `--check`; repair never does. |
| **R-006** | **Abandoned Lock Blocks Progress, and `unlock` Is Not Race-Safe:** A SIGKILL inside the critical section leaves a shard (or, worse, the repository-wide projection) unable to mutate until an operator intervenes. Separately, `unlock` reads the lock and unlinks it, and no `fs` primitive makes that unlink conditional on the bytes read, so a holder that releases and a new holder that acquires in between will have the *replacement* lock removed. | Medium (shard) / High (projection) | Accepted deliberately (ADR-0027 as amended, ADR-0030). The critical section is read-validate-write with no waits and the failure is loud and names its recovery command. Abandonment is classified by dead PID only, so a live slow holder never enters the recovery path. The Round 4 claim that nonce verification makes `unlock` race-safe is **withdrawn**, along with the undefined `wx` sentinel it relied on; `unlock` is maintenance-only and requires an explicit `--quiesced` operator assertion, with the nonce retained as a mistake filter. The compensating control is the unconditional CAS check inside the critical section, which turns a wrong quiescence judgement into a detected `CAS_CONFLICT` (or `DIGEST_INTEGRITY_MISMATCH`) rather than a silent lost update. |
| **R-007** | **Terminal-State Escape:** `completed` and `cancelled` have no matrix entry today, and the engine skips matrix validation when the source entry is absent, so a terminal task can transition onward. | High | Define empty-destination terminal entries and invert the guard to throw `UNKNOWN_SOURCE_STATE`; negative test every terminal outgoing transition (AC-009). |
| **R-008** | **Policy Gap Blocks Terminal Migration:** `bug-fix-workflow.yaml` defines neither `completed` nor `handoff -> completed`, so migrating issue-249 / issue-275 to a terminal state is illegal under current policy. | High | Additive policy amendment adding `completed`/`cancelled` and `handoff -> completed` (requires `closeout_evidence`), leaving `contract_version: 1` and every existing example-lane fixture untouched (enumerate the lane dynamically; do not assert a fixture count). |
| **R-009** | **Lock Pathname Moved by Archival:** A lock stored inside the shard directory is carried into `archive/{id}` by `renameSync`, so the owner's final release cannot remove it and the original pathname stops serializing anyone. | High | Store task locks in the stable `docs/records/work-items/.locks/` namespace and key the lock API by `task_id`; make `discoverActiveShards()` skip dot-prefixed entries before any shard-validity check so the namespace is not mistaken for a shard (AC-008). |
