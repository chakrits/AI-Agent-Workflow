| 1 | Is the durable envelope the sole contract authority, or does it layer over the existing `*-workflow.yaml` policies that `AGENTS.md` names canonical? | SA / Human | Resolved (Round 4): Layered, not sole. There is no matrix fallback for policy-silent transitions, no envelope-only allowlist and no exception contract; the matrix's `requires` is a design-time authoring aid never consulted at validation. The envelope's `workflow_id` is narrowed to `bug-fix` for Package 1. **Amended (Round 6, Blockers 2–3):** `bug-fix-workflow.yaml` gains a separate `resume` policy operation from `blocked`, limited to `investigating` and `verifying`, requiring `resume_evidence` and `approver_id`, and requiring the target to equal the most recent history event's `from`. |
| 2 | For CLI commands (`scripts/task-machine-cli.mjs`), should an optional `--force` flag exist for emergency Human Maintainer bypass of CAS digests, or must CAS always be strictly computed and supplied? | Security / SA | Resolved: CAS must always be strictly supplied; provide `inspect` command to display current digest for auditability without blind bypasses. |
| 3 | When `scripts/archive-work-item.mjs` moves a terminal shard, should it execute transactional archival with compensating rollback if status projection fails? | SA / Dev | Resolved (amended Round 7): use a durable archive journal; forward and compensating renames are separate task fenced commits, with projection commit between them and no nested commit guards (ADR-0029/ADR-0032). |
| 4 | Should an abandoned shard lock be reclaimed automatically after a staleness threshold? | SA / Security | Resolved (Round 4): No. No `fs` primitive makes removal conditional on the observed lock, so every automatic-reclaim variant can remove a live replacement owner. Fail closed with `LOCK_ABANDONED` and an explicit nonce-verified `unlock` command (ADR-0027). — **Amended (Round 5, Blocker 4, ADR-0027 amended):** still no automatic reclaim, and two further corrections. (a) Staleness is no longer an abandonment classifier at all: abandonment is **dead PID only** (`process.kill(pid, 0)` throws `ESRCH`), while age alone yields the non-destructive diagnostic tier `LOCK_ACQUISITION_TIMEOUT` + `LOCK_HELD_LONG`, so a live but slow holder can no longer enter the recovery path. (b) The Round 4 claim that nonce verification makes `unlock` race-safe — and the undefined "`wx` sentinel" it relied on — is **withdrawn**. `unlock` is a maintenance-only operation requiring an explicit `--quiesced` operator assertion; the nonce is retained only as an operator-mistake filter. — **Amended (Round 6, SEC-004):** ordinary lock-protected mutations prevent lost updates through mutual exclusion plus mandatory CAS, and CAS rejects a digest made stale by an already-committed write. After an incorrect `--quiesced` assertion removes a live or replacement lock, however, one-shot CAS cannot preserve mutual exclusion: two admitted writers can both compare the same pre-write digest before either writes, and the later rename can silently overwrite the first. The Human Maintainer rejected the residual on 2026-09-14. ADR-0032 requires a non-reclaimable commit guard plus durable fencing generation; Security and QA must validate the proof before SEC-004 can be marked remediated. |
| 5 | Is atomic replacement of `PROJECT_STATUS.md` sufficient to prevent lost updates to the root projection? | SA / Human | Resolved (Round 4): No. Atomicity prevents torn bytes, not read-compile-write interleaving. A projection-level mutation lock with a declared total lock order is required (ADR-0030). |

## 5. Scope

### In Scope
- **Core Pain Point 1 (Two-Layer Contract Model, `bug-fix`-Scoped Envelope - F-01, ADR-0026, ADR-0031):** Establish an explicit two-layer contract model rather than a single authority. The **storage envelope** layer (`docs/contracts/schemas/durable-task-envelope.schema.json`, `contract_version: 2`) owns file shape: the 11-state storage vocabulary, 64-char hex SHA-256 `state_digest`, strictly incremented `sequence_number`, history record shape. The **workflow behaviour** layer (`docs/contracts/{bug-fix,new-feature,config-change,data-change}-workflow.yaml`, `contract_version: 1`) keeps owning allowed transitions, required evidence and retry budget, exactly as `AGENTS.md` states today. Version binding is lane-specific: the legacy example lane compares `state.contract_version`; the active durable-envelope lane compares `state.policy_contract_version`. The policy is amended additively for terminal closeout and blocked resume without changing `contract_version: 1`.
  - **Package 1 durable scope is `bug-fix` only (ADR-0031).** The envelope's `workflow_id` and `change_type` enums are narrowed to `["bug-fix"]`, because the fixed 11-state vocabulary cannot represent the states `new-feature`, `config-change` and `data-change` policies require, and no `framework-meta-workflow.yaml` exists (verified: `docs/contracts/` contains only the four policies above). Both live active shards (`issue-249`, `issue-275`) are already `bug-fix`, so the narrowing migrates nothing. **Consequence, recorded deliberately:** `new-feature`, `config-change`, `data-change` and `framework-meta` — including Issue #277 itself — have **no durable shard** in Package 1 and remain governed by their policies and the existing example lane. The state enum itself is *not* narrowed: it stays a superset of the `bug-fix` policy's states (retaining `designing`/`planning`); the intersection rule, not the enum, does the narrowing.
  - **Transition authority rule.** A transition is permitted if and only if its destination appears in `TRANSITION_MATRIX[from].destinations`, the governing policy's `transitions` list contains the pair, and that row's evidence is present. Unknown or policy-silent transitions fail closed; there is no transition fallback.
  - **Policy-authoritative blocked resume.** `bug-fix-workflow.yaml` gains a separate `resume` operation with `from: blocked`, `destinations: [investigating, verifying]`, and `requires: [resume_evidence, approver_id]`. Resume also requires the destination to equal the latest into-`blocked` history event's `from` and the actor to be `human` or `orchestrator`. Missing Human evidence fails `HUMAN_APPROVAL_REQUIRED`; another target fails `INVALID_RESUME_TARGET`. Ordinary transition never consults the resume policy.
  - `bug-fix-workflow.yaml` is amended additively with `completed`/`cancelled` states and a `handoff -> completed` transition requiring `closeout_evidence`, so that terminal migration is legal under policy. Under the authority rule this leaves `cancelled` a valid **storage** state and a declared matrix terminal that is **unreachable by transition** in Package 1, since the policy enumerates no `-> cancelled` row; no wildcard semantics are introduced. `AGENTS.md` is amended to state the split explicitly.
- **Core Pain Point 2 (Actor Policy Validation & Trust Boundaries - F-02):** Mandate enforcement of `matrixEntry.actors` check in `transitionTaskState()` for every transition against canonical `ROLE_REGISTRY`. Reject unauthorized role attempts with `UNAUTHORIZED_ACTOR` error code. Clarify scope as caller-declared role authorization and document residual risk.
- **Core Pain Point 3 (True Atomic CAS & Mutual Exclusion - F-03, ADR-0027 as amended, ADR-0028):** Make `expected_digest` mandatory for state transitions and resumes. Implement a per-task mutual exclusion file lock in a **stable namespace that the archive rename never moves**: `docs/records/work-items/.locks/{expectedTaskId}.lock`, never `work-items/{task_id}/.lock`. Every mutating operation receives an explicit `expectedTaskId`; after acquiring that lock it re-reads the envelope and fails closed with `TASK_IDENTITY_MISMATCH` unless `current.task_id`, `expectedTaskId`, and the active shard directory basename are identical. `archiveWorkItem(expectedTaskId)` applies the same check before rename. This prevents two writers from holding locks for different identifiers while mutating the same pathname. The two canonical active-root exclusions — exact reserved entry `archive/` and every dot-prefixed entry — are applied before shard validation. **Fail-closed abandonment:** the engine never reclaims a lock automatically. Abandonment is classified by **dead PID only**; age alone is a non-destructive diagnostic tier (`LOCK_ACQUISITION_TIMEOUT` + `LOCK_HELD_LONG`) that never routes a live slow holder into a destructive path. The existing lock becomes a recoverable **admission lock**. Every admitted writer snapshots a durable generation, then must acquire a separate non-reclaimable commit guard and re-check both generation and disk digest inside that guard before atomic rename. `unlock` also holds the commit guard, durably increments the generation, and only then removes the admission lock; a false `--quiesced` assertion therefore makes prior writers fail with `FENCING_TOKEN_STALE`. Disk state is re-read inside the commit guard. A commit guard is never removed by online recovery. Implement dedicated `digestTaskEnvelope(envelope)` which excludes top-level `state_digest` and computes canonical RFC 8785 JCS SHA-256 via `scripts/lib/status-jcs.mjs`.
- **Core Pain Point 4 (Fail-Closed Projection & Transactional Archival - W1, F-10, ADR-0029):**
  - Unified validation seam: implement `validateEnvelopeSchema(data)` shared across state machine, compiler, and backfill tools. Enforce schema structure and `stored state_digest === digestTaskEnvelope(data)`. Throw `MALFORMED_SHARD` on unparseable, invalid, or digest-mismatched shards.
  - POSIX crash-durable atomic writes: implement `atomicWriteFileSync` with collision-safe `wx` temp files, write completion loops, failure cleanup (`unlinkSync`), `fsyncSync` data flush, atomic rename, and directory sync. A `writeSync` return of `0` is a fault, not a retry condition: the loop must throw `ATOMIC_WRITE_NO_PROGRESS` and clean up its temp file rather than spin.
  - Pure projection with explicit repair: `compileStatusProjection()` and `detectArchivedShardDrift()` are pure and write nothing; repair lives only in `reconcileArchivedShards()`, reachable from archival preflight and an explicit `--reconcile` flag. `--check` writes zero bytes and exits 1 naming a recovery command.
  - Projection transaction: serialize `PROJECT_STATUS.md` mutation behind a projection-level lock and re-read active shards only after acquiring it, under the declared total lock order shard lock -> projection lock.
  - Journaled fenced archival: persist transaction intent, fence both forward and compensating renames, publish projection under its own guard with no nested commit guards, and reconcile incomplete phases deterministically.

### Out of Scope
- Cryptographic agent identity verification or process authentication (caller-declared role policy validation only; full signature infrastructure deferred).
- Modifying production application business code or schemas outside control-plane state management.
- Modifying token budgets or Core Bootloader Tier 1 context limits ($\le 3,500$ tokens).
- Relaxing the 2-cycle rework retry ceiling or human approval gate invariants.
- Introducing external database engines or distributed network consensus mechanisms (remains Local-First, Git-Native, POSIX file-based).
- Automatic recovery from abandoned locks. Explicitly rejected in ADR-0027: recovery is an operator action.
- Online recovery of an abandoned commit guard. The guard is the non-reclaimable serialization root; removing it while an old writer might resume recreates SEC-004. Recovery requires stopping all repository writers and restarting the host/session before an explicit offline repair.
- Durable envelopes and active-shard enforcement for `new-feature`, `config-change`, `data-change` and `framework-meta`. Deferred by ADR-0031 to a later package whose entry conditions are a canonical policy per workflow (`framework-meta` has none today) plus a policy-aware state vocabulary.
- Wildcard transition semantics (`<any> -> cancelled`) in `scripts/validate-contracts.mjs`, which performs exact `from -> to` lookup today. Any future cancellation path must be enumerated as explicit policy source rows.

## 8. Business Rules

| Rule ID | Rule | Source | Impacted Area |
|---|---|---|---|
| **BR-001** | **Two-Layer Contract Authority:** The durable schema owns envelope v2 storage; workflow policies own transitions, resume, evidence and retry budget at policy v1. The legacy example lane binds `state.contract_version`; the active durable-envelope lane binds `state.policy_contract_version`. Transition legality is the strict matrix ∩ policy-pair intersection with policy-row evidence and no fallback. Resume is a separate policy operation from `blocked`, limited to the recorded interrupted state (`investigating` or `verifying`) with `resume_evidence`, `approver_id`, and Human/orchestrator actor. Unknown workflow/source, policy-silent transition and unauthorized resume fail closed. | Audit F-01, Round 6 Blockers 2–3, ADR-0026, ADR-0031 | Task State Machine, JSON Schemas, Workflow Policies, `validate-contracts.mjs`, AGENTS.md |
| **BR-002** | **Strict Matrix Actor Authorization:** Every state transition must enforce actor authorization against `TRANSITION_MATRIX[fromState].actors`. Canonicalize actor identifiers to lowercase kebab-case against `ROLE_REGISTRY`. Unauthorized transitions fail closed with `UNAUTHORIZED_ACTOR`. | Audit F-02, Least Privilege Principle | `scripts/lib/task-state-machine.mjs`, CLI |
| **BR-003** | **Mandatory CAS, Identity Binding & Fenced Commit:** All state modifications and resumes supply `expected_digest` and run inside `mutateTaskStateOnDisk(rootDir, expectedTaskId, ...)`. `.locks/{expectedTaskId}.lock` is a recoverable admission lock. The writer snapshots `.fencing/tasks/{expectedTaskId}.json.generation`, computes from that state, then acquires `.commit-guards/tasks/{expectedTaskId}.guard` with `wx`. Inside this non-reclaimable guard it re-reads generation and envelope, verifies identity, `expected_digest`, and generation, then atomically renames. `unlock` acquires the same guard, atomically persists `generation + 1`, then removes the admission lock. No online command removes a commit guard. A stale writer fails `FENCING_TOKEN_STALE`; retry requires reacquire, reread, new digest, and recomputation. | Audit F-03, Round 6 Blockers 1/4 and correction 2, ADR-0027, ADR-0028 | `task-state-machine.mjs`, `task-machine-cli.mjs`, `archive-work-item.mjs` |
| **BR-004** | **Fail-Closed Projection & Read-Only Checks:** Projection compilation must never skip malformed, invalid, or digest-mismatched shards silently. `compileStatusProjection()` and `detectArchivedShardDrift()` are pure and write nothing; repair exists only in `reconcileArchivedShards()`, reachable from archival preflight and explicit `--reconcile`. `--check` writes zero bytes and exits 1 with a named recovery command, and creates no lock namespace. Archival failure triggers compensating rollback. Exactly two canonical active-root exclusions are permitted before any shard-validity check: the exact reserved entry `archive/`, and any entry whose name begins with `.`. The dot-prefix rule is non-lossy because `task_id` cannot begin with `.`, while `archive` is a reserved root name and must be rejected as `RESERVED_TASK_ID` for active work. Any other skip is fail-open. | Audit W1, F-10, Round 6 correction 3, ADR-0027, ADR-0029 | `compile-status-projection.mjs`, `archive-work-item.mjs` |
| **BR-005** | **Projection and Fenced Archive Journal:** Projection uses its admission/generation/guard. Archive journal is strict, digest-protected, exclusively created, revision-conditional, and binds immutable intent/txid/task/source generation+digest. Directional phases and distinct terminal outcomes remove location ambiguity. Generation advance is handled only by guarded append-only adoption of the same intent with a fresh attempt ID; all candidates are recomputed. Task/projection commit guards never overlap. Cross-file atomicity is not claimed; exhaustive matrix-driven reconciliation gives detectable convergence. | Round 4/7/8 blockers, ADR-0029, ADR-0030, ADR-0032 | `compile-status-projection.mjs`, `archive-work-item.mjs` |

## 9. Risk / Edge Case Notes

| Risk ID | Risk / Edge Case | Impact | Suggested Coverage |
|---|---|---|---|
| **R-001** | **Legacy Active Shard Incompatibility:** Shards for `issue-249` and `issue-275` currently have `contract_version: 1` and lack `sequence_number` and `state_digest`. | High | Provide a deterministic migration / reconciliation backfill script to upgrade active shards to v2 format prior to activating strict schema gates. |
